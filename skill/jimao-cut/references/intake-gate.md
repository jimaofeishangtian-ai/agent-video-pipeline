# Consolidated intake gate

Run this gate once before creative design on a fresh build. Skip it for a specific revision, an explicitly complete brief, or a user instruction to proceed without questions.

## Interaction contract

1. Inspect the source, transcript, references, project state, and personal profile first.
2. Ask only choices that materially change the result. Reuse known answers and do not ask for technical details Codex can inspect.
3. Present one structured card or form when the host supports it. Otherwise send one compact numbered choice set in chat.
4. Recommend the profile-backed option first and say in one sentence why it fits this source.
5. Use at most six fields. Include an “I will describe another style” option for visual direction. Combine related choices so a script/deck route still fits in one submission.
6. When visual cards are supported, show three genuinely different directions with preview images plus the custom-description option. Do not treat an example card's styles as selected preferences.
7. Wait for one submission, summarize the locked brief once, and begin. Do not reopen intake during normal execution.

## Candidate fields

Include only unanswered fields:

- purpose/destination and target viewer;
- visual direction;
- edit density: restrained, balanced, or high-density;
- evidence strategy: real UI/evidence first, mixed, or motion-led;
- caption language/mode;
- must-keep material, forbidden treatments, or paid-generation boundary.

## Conditional fields

When there is no usable recorded speech, include **narration source** as a required field with only locally available choices:

- user will provide or record a voice track;
- use an authorized existing recording from the supplied assets;
- generate TTS with a selected available voice;
- use an explicitly authorized cloned voice;
- build a silent timing prototype first.

Recommend the least costly reversible option that fits the brief. State paid credits, logins, voice-cloning consent, or external upload before execution. Do not infer consent from possession of an audio file.

For PPT/PPTX/PDF-deck input, include **adaptation level** when unanswered:

- `reinterpret` — preserve facts but rebuild the story and visual grammar for video;
- `balanced` — retain the deck structure selectively while redesigning scenes;
- `faithful` — keep slide order and wording unless required for timing.

For a deck or faceless script, offer three profile-compatible visual directions when visual cards are supported: line-art blueprint, playful marker/editorial sketch, and clean semantic motion; include the custom-description option.

Do not ask the user to choose an engine, codec, command, or internal workflow unless two ownership choices would materially change editability or cost. Engine selection is the Skill's responsibility.
